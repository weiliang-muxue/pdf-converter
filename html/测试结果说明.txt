HTML / Nginx 版 v1.0.2 验证记录
日期：2026-11-02

实际环境：Windows 10 专业版 10.0.19045 x64；Edge 156.0.4314.50；独立测试用 Nginx 1.30.6。

通过的真实操作：
1. 只复制单文件网页，运行自动启动脚本，识别 Windows10 / AMD64 并启动服务。
2. 自动找到 Nginx 运行实例及其 -p / -c 参数，找到 /pdf/ 网站目录。
3. 自动备份、写入 Word 代理、检查并重新加载 Nginx，无需手工编辑配置。
4. 再次启动复用同一个 PID 和口令，配置中只保留一个自动块。
5. 故意生成无效指令，Nginx 拒绝；原配置逐字节恢复，随后 nginx -t 通过。
6. ZIP 图片实际输出顺序为 1、2、3、10；多图通过上移、直接页码、拖动形成 2、3、1。
7. DOCX 和旧版 DOC 均通过自动配置后的 /pdf/word-api/ 真实转换并下载。
8. Word 网页显示服务器名称、CPU 和自动选择的程序；下载地址不携带私有口令。
9. 独立 PDF 解析核对页数、页序、A4、96 DPI 尺寸、透明背景、EXIF 旋转、中文文字和分页。
10. 纯静态部署和直接打开 HTML 均可处理 ZIP / 图片；没有 Word 服务时明确显示未就绪。
11. 异常 ZIP、路径穿越、虚假解压大小、CRC 校验失败、密码 ZIP、无效图片均有错误提示。
12. 取消处理保留文件列表；375 像素宽度无横向溢出；无 JavaScript 异常。
13. 浏览器测试禁止外部请求，未发现任何外部网络调用；ZIP/图片转换没有调用服务器接口。

源码检查：13 项 Go 测试通过，go vet 通过；JavaScript 和 Shell 语法/核心逻辑检查通过。
系统识别模拟：Win7 SP1 32/64 位、Win10 32/64 位、Win11 64 位选择符合规则；旧系统、缺 SP1、未提供的 Windows ARM64 拒绝。
Linux 模拟：openEuler、麒麟、统信分别搭配 x86_64、ARM64、LoongArch64 的 9 个识别组合通过；MIPS 和旧 LoongArch 内核拒绝。
这些模拟测试只调用 --check，不运行 Linux 二进制或挂载运行环境。

未完成实机验收：Windows 7、openEuler / EulerOS、麒麟、统信、Linux ARM64 / LoongArch64。
信创主程序已重新编译；离线运行库沿用已经校验依赖闭包的交付包。不能把识别测试、交叉编译或依赖检查等同于实机认证。
